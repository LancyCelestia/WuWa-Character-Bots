## 2. 改法与理由

机械修（`ruff check <四件> --select I001,RUF100,UP035,F401 --fix`，9 枚）：
import 排序（G1 `68:1`、w1 `27:1`）；删四处 unused noqa（E402×3 + ANN401×1）；
`Callable` 迁 `from collections.abc`（w1 `36:1`）；删 `WriteTrace` import（d2 `48:5`）。

手改（逐枚）：

1. G1 件 I001 fix 把原 79 行「字段集…普查真身」注释排到 straight import 前、原 64-67
   「悬空动词台账＋副作用报备」注释块脱离其 import——已把两块注释各归位到
   `scripts.config_read_point_census` 与 `tests.test_trigger_matcher_ratchet` 的 import 前，
   并统一加普通注释「以下三条 import 有意置于 sys.path.insert 之后（中段 import＝E402
   场景）」——noqa 承载的意图改由普通注释表达（工单第 1 条要求）。
2. G1 件 `912`：`sorted(registered)[0]` → `min(registered)`（FURB192；`registered` 为
   set[str]，此处取最小元语义与原式逐点等价）。
3. G1 件 `999`：`_, alias_bucket2, has_prefix2 = …` → `_, _, has_prefix2 = …`——
   三元解包是刻意的形状断言（E3 腿必须吃满三槽），不删槽位只换 `_`（RUF059）。
4. d2 件 `272`：`sorted(name for name in names if …)[0]` → `min(name for name in names if …)`
   （前一行 `any(...)` 已断言非空，IndexError/ValueError 差异不可达）。
5. d2 件 `474` / `505`：两处嵌套 if 合并为带括号折行的单一 if（SIM102；条件逐字保留，
   折行防 E501）。
6. w1 件 `233`：删 noqa 后补普通注释「Any 进出有意：假 provider 只转录」（意图存注释，
   不留死 noqa）。
7. w1 件门修 `_code_string_constants`：`{id(tree.body[0])}` → `{id(tree.body[0].value)}`。
   机理复核：模块 docstring＝`Module.body[0]=Expr(value=Constant)`，旧码记的是 Expr 包装
   节点的 id，而 `ast.walk` 吐出的是内层 `Constant` ⇒ 排除集永远打不中模块 docstring，
   `TRUSTED_SYSTEM`（仅出现于模块 docstring）泄进「代码字符串」集，误伤判据 ③ 的
   威胁面说明断言（即那枚红的根因）。与函数 docstring 分支（记 `id(body[0].value)`）同款。
   生产件 `prompt_template.py` 零改动。
8. seat_t1 件 `229`：嵌套 if 合并为带括号折行的单一 if（SIM102；条件逐字保留）。

d2 件既有红测试腿（quirks 记账格）**未顺手修**：本次只动 lint 面，该腿读数改前改后一致。
