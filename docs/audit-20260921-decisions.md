# 第一档：安全与账号，建议今天定（4 条）

## 1. 别人在群里发一条链接，就可能把你 bot 的 18 个平台登录号全偷走

**现在会发生什么**：任何群成员（不需要管理员）发一条精心拼的链接，比如
`https://一个他控制的网站/?r=https://steamcommunity.com/app/123`。
机器人一看「里面有 steam 字样」就按 B 站/Steam/微博那套规则去解析，但**实际请求发到了他的网站**，
而且**把你存在这台机器上的该平台登录凭证一起带过去了**。他拿到凭证就能登你的 B 站、微博、推特、Steam、网易云等账号。
我数了一下：受影响 **18+2 个平台**，触发条件低到「在群里发一条文本链接」。

还有一条共犯的通道：我已经实测确认，这台机器上的 Python 在**跳转网址时不会把登录凭证摘掉**
（浏览器会摘，Python 的这套库不摘）。所以「先发到正规站、再一跳转到他的站」也能偷走。

**为什么我没顺手修**：修的位置有三条出口（三种发请求的方式），要一次性都堵；而且**唯一能证明"没改坏"的办法
是拿 18 个平台的真实链接各发一条去验**。你休息的时候我不该替你出网，更不该拿你的登录号去试。
半修的风险是让 B 站解析悄悄坏掉（它本来就挑剔），而这种坏目前没有测试能抓住。

**修好之后你看到什么**：机器人只会在「这个凭证本来就该发给的那个网站」上带凭证，其它一律不带；
跳转跨站时自动摘掉。解析功能一切照旧，攻击链接会被它当成普通外部网站，最多解析失败一句人话。

**要你回**：
- **A.** 我直接修，接受「需要你真机抽验 3–5 个平台」这一步（建议）
- **B.** 先只修「跳转摘凭证」这一半（改动最小、零风险），另一半等你安排时间一起验
- **C.** 先堵临时办法：把所有平台的登录 cookie 文件暂时撤掉（解析会退化成"未登录态"，部分平台会解析失败，但不再可能被偷）

## 2. 说繁体话就能绕过「未成年」这条死线（我已修一半，剩一半要你定）

**现在（修之前）会发生什么**：同一句违规内容，用简体写会被拦，**用繁体写就直接放行**。
比如「她12歲做愛」这种，机器人完全不觉得有问题，因为它认死的字是简体的「岁」「爱」。
这条是**全项目唯一一处"哪怕管理员开了放行也必须拦"的红线**，所以后果最重。

**我已经做了什么**：加了一张繁简对照表（95 组字），只在"判断违不违规"这一步做转换，
不会改动你看到的任何文字，也不会影响命令触发词（触发词那边你之前明确说过不做繁简转换，我没动）。
顺手补了另外两个同族洞：数字和「岁」之间加空格（`12 岁`）原来也能绕过；另外五条死线的英文词
被中文紧挨着写时原来会漏（`我要mutilate她`）。
**这些改动都带了新测试，修之前 18 条测试红、修之后全绿，而且确认没有把正常句子误杀。**

**要你定的是"修到什么程度算够"**：
- **A.** 引入一份完整的繁简对照表（最彻底，代价：仓库多一张要维护的表）
- **B.** 维持我这次的字级表，以后**每次往安全词表里加新词，必须同时登记繁体写法**，并把这条做成机器检查（建议：便宜、且不会悄悄退化）
- **C.** 接一个现成的繁简转换库（最省事，但给你的项目多一个外部依赖）

## 3. 南极 0.6 级小地震，也可能在凌晨三点给你弹「红色预警」

**现在会发生什么**：紧急信息那条链子上有三个洞叠在一起——
① 抓地震数据时**没有设震级门槛**（把全球一小时内所有地震都抓回来，包括 0.6 级）；
② 只要标题带「地震」两个字就被定成最高级「红色预警」；
③ 「红色预警」允许**击穿凌晨静默时段**。合起来就是：**深更半夜推给你一条毫无意义的地震警报**。
更糟的是：你当初裁定的那道「4.0 级以上才收」的过滤，**代码写好了但生产环境根本没调用它**。

**修好之后你看到什么**：小地震根本不进库；红色预警要么真的红色，要么不响；凌晨只推真正紧急的事。

**要你回**：
- **A.** 按你原裁定接回 4.0 门槛 + 取消「地震」这两个字自动定红（建议）
- **B.** 只接回 4.0 门槛，定级规则先不动
- **C.** 这条先记着，等你要启用紧急信息域时一起处理（现网该域名单没填＝本来就不推，风险是"启用那天才踩"）

## 4. 语音引擎卡住时，机器人会整条链路变慢（而且不会告诉你）

**现在会发生什么**：语音引擎有个「连续失败就歇一会儿再试」的保护（你之前专门要求做的）。
但代码里有个顺序错了：**成功与否的判断跑在保护之前**，于是引擎用"回了一段纯静音"这种方式坏掉时，
那个保护**永远不会启动**，机器人每条语音请求都白等几十秒，还会占住干活的工人，把普通聊天也拖慢。

**修好之后你看到什么**：语音坏 → 一句话明确告诉你「语音暂时不行」（这本来就是你要的效果）→ 后续请求快速失败不再干等 → 聊天不受牵连。

**要你回**：**A.** 修（建议，改动很小）/ **B.** 等真机观察到慢再修。

# 第二档：会影响你日常使用的毛病（5 条，选做）

## 5. 问「美元兑人民币行情」，回给你的是全球股指面板

三条不同命令的优先级**数字完全相同**，谁赢全看它们在表里谁排得靠前。现在「汇率」排在「行情」后面，
所以你问美元兑人民币，拿到一叠指数行情。另一条「国债行情」是**碰巧排对了**才正常——以后谁改表顺序就翻车。

- **A.** 给这三条各自不同的优先级 + 加一条「不许同优先级抢同一句话」的检查（建议）
- **B.** 只把汇率排到行情前面（一行改动，治这一次）
- **C.** 不修，登记

## 6. 机器人"晚上复盘"出来的东西，第二天完全用不上

机器人有夜间反思（把你长期稳定的偏好归纳成"高层事实"）。实测：这些事实**存进去了，但取的时候
用的钥匙和存的钥匙不一样**，所以**一条都召不回来**——你在群里聊了很久沉淀下来的画像，其实一直没生效。
好消息是方向"安全"：不会把别人的事泄露给你，只是白做了。

- **A.** 修（建议，但要先定怎么修，因为动的是数据库里的键，涉及运行数据）：
  A1 把取的时候也拼成同样的钥匙（改动小）/ A2 给数据库加一列干净钥匙（要多一次迁移，我会先备份）
- **B.** 不修，把夜间反思这个开关关掉，省得白烧模型配额
- **C.** 先只加一条"召回数为 0 就告警"的观测，等真机数据出来再定

## 7. 「我刚才翻滚躲开了」会被当成骂人，扣你好感度

好感度判定里有个"滚"字，排除词只写了「瓜/烂/烫」。而**「翻滚」是鸣潮的核心动作词**——你在聊游戏时的正常句子
会被判成被侮辱，掉一点好感分（有上限，伤不大，但信号是错的）。
- **A.** 补排除词（翻滚/滚动/滚雪球）+ 顺手把「我滚去睡了」这类也放行（建议）
- **B.** 不修（伤害确实小）

## 8. 管理员改的运行时设置，可能重启后悄悄没了（我已修成"会告诉你"）

原来落盘失败**一行日志都不打**，你看到"设置成功"，重启后那条没了。我改成：一旦落不下去就打错误，
并且明写「重启后会丢」。
- **A.** 保留这个改动（建议）
- **B.** 嫌日志吵，降级成警告

## 9. 「平台共享导出」这个功能一直是 0 条数据（我已修）

它是为"多个机器人共享脱敏记录"预留的，默认关着。修之前它查数据用错了键的写法，**永远查不到群记录**，
而且会把群记录误标成"个人隐私级"（方向反了）。已按之前修过的同类问题的正解改好并上了锁。
- **A.** 保留（建议）
- **B.** 这功能压根不要了，退役掉

# 第三档：工程路线决定（4 条，影响后面怎么干活）

## 10. 那个 1931 行、生产一次都没用过的"中央调用壳"，删不删

AI 绘画那条线的接口就挂在这上面。两个独立席位读完全部代码后的判断是一致的：**AI 绘画的对接不需要它**，

- **A.** 退役它，只保留里面真正有价值的两小块（约 380 行）：调用器 + 那个"真的回磁盘核对"的校验器。
  净减约 1200 行（建议）
- **B.** 留着当 AI 绘画的骨架，先把接线做完再说
- **C.** 不删，但先立一条门：不许再有新代码 import 它（防它长大）

## 11. 占卜功能在库里存了**两套完整实现**

同一件事（抽牌、存档、算运气等级、随机种子）写了**两份**，一份给聊天用、一份给后台面板用，
两边数据库结构还不一样。后果：你在聊天里抽的牌，后台看到的可能是另一套账。这是本次深读新发现的，
以前所有报告都没登记过。

- **A.** 以**后台那套**（结构更新）为真身，聊天侧改成薄壳转发（建议）
- **B.** 反过来，以聊天侧为真身
- **C.** 两套都留，但强制共用同一个存储实例（改动最小，问题也最小）

## 12. 「所有内容实时自动同步」这条要求，到底还做不做

审计结论：你提的三把尺子里，**"实时自动同步"这一条目前是 0 分**——全仓没有任何一处是"源码一改，副本自己跟着变"；
所有同步都要人跑一条命令或跑一次测试。唯一的例外是一台"巡检器"（它专门盯 6 处容易漂的东西：人格文件、
配置样例、命令手册、库清单、路由表、语音文档），但它**三重死亡**：没进版本库、启动时没被调用、
它想读的 7 个配置项在项目里根本不存在——所以它的告警开关永远关着。

- **A.** 救活它：补那 7 个配置项 + 接进启动流程，让它真的定时巡检、漂了就私聊告诉你（建议，
  这是唯一能让这条尺子有落点的办法）
- **B.** 承认不做"实时"，改成"每次重启前强制体检"（现在已有一半：重启预检脚本），并把这条要求从目标里划掉
- **C.** 维持现状（那就是继续 0 分，而且每次改配置都会有人踩"文档和代码不一致"）

**我故意没改它的基线数字**，因为改数字＝洗绿，正是这份报告定罪的那类手法。

- **A.** 授权我批量修：把这些"会过期的数字"从叙述文档里删掉或改成指向机器册（`docs/auto-facts.md` 是唯一每次都准的），
