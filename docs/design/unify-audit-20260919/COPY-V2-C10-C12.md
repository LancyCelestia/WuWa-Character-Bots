## 我判定「不可写」所以没写的事实（逐条给理由）

| # | 没写的话 | 为什么不可写（核实到的实况） |
|---|---|---|
| 1 | 「跟我说一声就帮你删掉某条／改某条」 | 收件箱命令面只有"记"和"看"两个动作（append + read_pending），全树无删除/改单入口；清档是早报 `archive_inbox` 的副作用 |
| 2 | 「到点我会再来提醒你这一条」 | 提醒是另一能力（reminders）；daily_assist 命令面没有任何"稍后再提醒"路径，到点链只走早报/晚报调度与推送名单 |
| 3 | 「没记清的话我会再问你一句」 | 无追问路径；正则匹配后直接落条目，2000 字外直接截断不回头确认 |
| 4 | 「发丢了会自动重记一次」 | `append_inbox_line` 单次写入；无自动重试（全波统一口径：自动重试一律不可写） |
| 5 | 「明晚的晚报里也有一条属于你」 | 待处理段在**早上 09:00 早报**时归档清空，晚报对账的是"今早归档的条数"；给收件箱文案承诺"晚报"会串档 |
| 6 | 「每条都还在你发我的原话状态（一字未删）」出现在**清单池之外** | 清单可写"一字未改"（pending 原样读回属实）；**C12 转发不可写**——正文有 1500 字截断 + `redact_local_secrets` 打码，"原话完整"两头都骗人 |
| 7 | C11「我每天都把摘要送到这个群」 | 当日无可用摘要（provider 未启用/空摘要）该群**静默跳过**，推送并非无条件每日发生；本稿只写"今天这一趟"的此刻行为 |
| 8 | C11「已经替大家理成了几条要点」 | LLM 压缩失败/未启用时正文回退**确定性逐行清单**，不是要点；开场两态必须都读得通，故全族零"要点/提炼"措辞 |
| 9 | C11「每一条原话我都替大家留着」 | LLM 成功态是 3-5 条压缩摘要，"原话逐条"不成立；同理禁"原样"二字（本稿 C11 零出现） |
