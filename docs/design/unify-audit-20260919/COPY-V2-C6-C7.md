### C6 判定为「不可写」而没写的事实

- **自动重试 / 稍后我替你重试**：代码里没有（错误卡路径不做任何重试；两段式只做"文本先行、卡后补发"，补发的是卡不是那次指令）。
- **主动追问 / 我再回头问你一句**：无此路径；错误卡一次性提交，之后零动作。
- **我替你转给创造者 / 已经上报**：`help_text` 只有"转给创造者"这一**用户手动**动作；bot 侧无转发路径（告警走 runtime 事件日志，不发给开发者）。
- **完整栈也在这张卡（这段文字）上**：不实——卡上是末 N 帧摘录（`_STACK_FRAMES_MAX=30`，生产缺省 8 帧），完整栈在 runtime 事件日志（E-11 如实口径）。
- **冷却期内的说法**：C6 两池与冷却池不混——冷却降级文本压根不带指引句（`cooldown_line` 只发 `:91-104` 那一句）。
- **"再发一次就能成"**：属 C5 人话区职责（`_HUMAN_TEXTS` 已写"要重试就再发一次"），页脚与它同屏出现，重复即噪声，本稿刻意不写。
- **把"悲鸣/残象"当故障比喻**：批次单 §一 明禁（世界观语境错位），一条未用。
- **"我在这/我守在这里/等你再问"在场承诺族**：C6 是信息句，一律不入。

## 二、C7 提醒到点五型（每型 1 → 6-8 条）

> 五型名以代码常量表为准：`medicine` / `appointment` / `shopping` / `todo` / `custom`（`REMINDER_KINDS`）。
> 现行字面均为三行（到点信号 + 事项复述 + 温柔收尾），`\n` 相联、整条一次发出；本稿**保持三行结构**（首行信号、次行带 `{text}`、末行收尾——顺序可变），
> 每条**恰含一个** `{text}`，逐字与旧句一致（不写成 `{content}` / `{name}`）。
> 表中 `\n` 即代码里的换行转义；首条 = 现行原句，其余为新增变体。
> 分型语义提醒：`medicine` 的关键词含**输液/打针/复诊/体检/滴眼药**，故新增条刻意写成"顾身体"的通用口径，只保留一条点到"药"字（见文末登记第 3 条）。
