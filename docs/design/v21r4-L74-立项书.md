## 二、验收重点（从矩阵行拆解）

1. **真实产物 admin 可取**：音频/卡片/绘图/视频等产物不是「run 内部存在即算」，必须走到 admin 实际可取。
2. **四步证据**：每件产物逐场景记录 生成成功/资产校验/平台投递回执/admin 有权获取 四步状态；缺任何一步不得宣称交付完成。
3. **不伪称已观看**：状态机里不存在「已观看」档（平台无 read receipt=不可知）；「已投递」以平台回执为准，不得超报。
4. **受控交付**：摘要+合集默认 ≤5 直接附件，其余走授权接口；下载凭 asset_id+身份/作用域检查+短期授权，不裸露 Runtime 路径。
5. **保留期与配额**：报告 30 天/大资产 7 天/失败证据保护/满额拒新 run 不删审计。
6. 隐含（扩展 §8.2:261）：blocked/skipped/unknown 不得算 pass；fake 与 live 严格隔离，不把 fake 结果混入 live。

## 四、立项方案要点

### 4.1 产物登记（ArtifactStore）

- 布局：run_id 隔离目录 + asset 旁车 json（sha256/mime/尺寸或时长/来源场景/生成参数摘要/四步状态各档时间戳）；sha256 去重可参考媒体归档既有先例（形态参考，不共库）。
- 路径纪律：一切出站引用只给 asset_id；Runtime 真实路径不出现在 REST 响应/命令输出/附件文件名（§8.2:281）。

### 4.2 admin 拉取入口（G3，本立项核心交付）

- REST：控制面（既有 loopback+Bearer 认证面）下 `GET /acceptance/scenarios|runs|runs/{id}|runs/{id}/artifacts`（§8.2:279 原文）；run 写操作（POST run/cancel）须管理员+授权包（§8.2:279）。
- 下载授权：asset_id+身份/作用域检查+**短期授权 token**（一次性或短 TTL）；默认拒绝未列动作（§8.1:253 授权包语义同构）。
- 命令：`/bot acceptance list|run|show|artifacts|retry`（§8.2:279），进 echo 帮助注册表——**实现后才进现行 help**。
- SSE：`artifact.ready`/`run.finished` 事件（§8.2:279）——依赖控制面 SSE 既有面，落点待接线席。

### 4.3 主动交付与「不伪称已观看」

- admin 收摘要+受控合集（默认 ≤5 直接附件，其余指路授权接口）经 SendQueue 私聊 submit；**绝不发触发群**（对齐 §7.2:241 私有 admin 会话口径）。
- 状态机枚举封顶：`generated → validated → delivered(receipt) → fetchable`；**无 viewed 档**。附件送达 ≠ 已观看，文案与字段命名都不得暗示。
- 四步状态逐场景落进 RunReport 持久化件，run 摘要与 admin 通知引用同一事实源。

### 4.4 保留期/配额/cleanup

- 报告 30 天、大资产 7 天（§8.2:281）；「未关闭失败证据受保护」——失败 run 的资产在 incident 关闭前不 prune；配额满先拒绝新 run，不删审计。
- cleanup 只处理登记资源（测试数据带 run_id），零误伤。

### 4.5 诚实边界（分期交付的现实约束）

- **产物源现状**：四步断言之第 1/2 步依赖产物源场景真实落地（TTS/绘图/ASR/视频属 S10 协议域与 L51/L52，production_wiring 均 not_wired）；**当前真实产物源只有既有能力**（卡片 PNG/音频类）。本立项先建「入口面+登记面+取件面」，对既有真实能力先通四步闭环；其余场景产物源落地后自动受益——入口面与产物源解耦，不空等。
- mode 字段贯穿（fake/live，§8.2:259 AcceptanceRun 含 mode）；`NotWiredTransport` :284 的诚实先例（测试 :553）延续到产物面：无真件不造件。
