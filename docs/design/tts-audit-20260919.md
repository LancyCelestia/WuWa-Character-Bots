| 坑 | 现象 | 解法 |

| **① `--basetemp` 放在仓库内 → 大量假失败** | **本席实测：basetemp 在仓库内时全量 30 failed + 4 errors；挪到仓库外后只剩 2 failed**（且那 2 项是别的席位的问题）。原因：多个测试的 fixture 会 `assert not destination.is_relative_to(REPO_ROOT)`（断言临时副本不能落在源树内），还有些测试会扫全仓文件、把 `tmp_path` 里的样本当成真实源码。**basetemp 在仓库内 → 这些断言必炸** | **`--basetemp` 一律给仓库外路径**，如 `C:/Users/LancyCelestia/.workbuddy-ai/tmp/pytest/<name>` |

## 4. 核心算法说明（供审计者判断「逻辑对不对」）

### 4.1 确定性哈希概率门

```python
seed = f"{message.session_id}:{message.message_id or message.request_id}"
bucket = int(hashlib.sha256(seed.encode("utf-8")).hexdigest()[:8], 16) % 10000
return bucket < probability * 10000
```

**审计要点**：
- `hexdigest()[:8]` = 32 bit → `% 10000` 映射到 `[0, 10000)`。**取模偏差可忽略**（2³² / 10000 ≈ 429496，偏差 < 0.003%），但严格说**不是均匀的**。这是项目既有惯例（`gate.py:106-117` 同款），本席**沿用不发明**。
- **同一条消息结果恒定**：`seed` 只依赖 `session_id` 与 `message_id`（无 message_id 时退到 `request_id`）。
- **边界**：`probability <= 0` → False；`probability >= 1` → True（**先判边界再算哈希**，避免 `0` 与 `10000` 的浮点比较问题）。
- ⚠️ **若 `message_id` 与 `request_id` 都为空** → `seed = "session_id:"`，同一会话所有消息**共享同一结果**（要么全配要么全不配）。本席认为实际链路里 `request_id` 必有值（`IncomingMessage.request_id` 有 `default_factory=new_request_id`），故不构成实际风险——但**这是一个可被证伪的点**，见 §6.1。

### 4.2 六道门链（`should_voice_reply`）

顺序**有语义**，不能调换：
1. `bot_tts_enabled` — 总开关（关=整个能力不存在）
2. `bot_tts_auto_reply_enabled` — 自动配音开关
3. `result.audio` 非空 → 已有音频，不叠加（防双语音）
4. `capability_id == "bot.chat"` → 只管人格对话（不碰命令式能力）
5. `auto_reply_scope_allows` — 会话范围
6. `always` 旁路 / 概率门

**审计要点**：前五道**都是廉价的**（纯内存判断），第六道才涉及哈希计算。所以把谓词提到 `__init__.py`（第二批）能省的是**线程池调度**，不是哈希计算。**本席未做这一步，不影响功能。**

### 4.3 错误体解析（修 bug 的核心）

```
HTTP 400 body: {"message": "tts failed", "Exception": "参考音频在3~10秒范围外，请更换！"}
                                                    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 真原因在这

旧：detail = error_body.get("message") or error_body.get("Exception")  → "tts failed"（真原因丢失）
新：detail = error_body.get("Exception") or error_body.get("message")  → 真原因（正确）
```

> 变量名在第二批由 `payload` 改为 `error_body`（见 C30）。改名的**唯一原因**是第一批复用了 `payload`——与同函数上方的请求体 `payload: dict[str, Any]` 撞名，mypy 报 2 条 error。**语义零变化**，只是不再重名。

**审计要点**：
- `or` 的短路语义是**关键**：`get("Exception")` 非空就取它。若引擎某天返回 `Exception: ""`（空串），会回落到 `message`——这是**期望行为**（有值就用，没值才退）。
- `response.json()` 在旧代码里被调了**两次**；新代码只调一次并缓存到 `error_body`。若引擎返回非 JSON，旧代码靠 `except` 兜到 `response.text`，新代码走 `error_body = None` → `else` 分支 → `response.text`。**两条路径等价，但新的不会因二次调用抛异常。**
