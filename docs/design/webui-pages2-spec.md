## §0 版式宪法（摘要，详条 = adoption §八）

1. 字号只允许五档：text-xs 12px / text-sm 14px / text-base 16px / text-lg 18px / text-xl 20px；
   禁 `text-[…]` 任意值与五档外类（text-2xl 及以上一律不许）。
2. 间距只允许 4px 栅格刻度 {4,8,12,16,24}px → Tailwind {1,2,3,4,6} 档；刻度外（p-5/p-8/gap-8
   等）与任意值间距禁用。
3. 圆角三档 30/18/14（rounded-xl/lg/md，index.css 已钉值）；rounded-full 仅限 chip/徽章/头像胶囊。
4. 零硬编码色值：颜色只经语义 token 与 --chart-1..6；tsx 内禁 #hex/rgb()/oklch() 字面量；
   canvas 取色用 getComputedStyle 读 token。
5. 页面全部由既有可复用组件拼装；三页验收口径 =「新写 CSS 类=0、新增 .css 文件=0」。

## §1 知识库页 `/knowledge`

**数据**（形状以 progress-BACKEND2.md 为准）：
- `GET /api/v1/knowledge/collections` → 集合列表（社区梗/黑话库/鸣潮/战双等二次元库）；
- `GET /api/v1/knowledge/terms?collection=&q=&page=` → 词条分页列表。

**布局**（自上而下）：
1. PageHeader：标题「知识库」+ 副题（说明库来源与只读性质）；搜索框置于页头下方**居中宽布局**
   （max-w-2xl 居中，占位符「搜索术语 / 别名」）。
2. 集合子导航：**顶部 CategoryChip 行**（裁决：不取左栏——单文件仪表盘保持满宽内容区，集合数
   ≤12 时 chip 行版式最稳；>12 再评估左栏并记入 progress）。可用集合=可点 chip，选中态=品牌色；
   `not_available` 项=灰态 disabled chip（不可点、附「未启用」标，不给假详情）。默认选中=列表
   第一个可用集合。
3. 词条卡网格：**统一等宽 3 列网格**（裁决：弃 masonry——等宽保版式一致）：
   `grid grid-cols-1 md:grid-cols-2 xl:grid-cols-3 gap-4`。卡片（SectionCard）内容固定四行：
   术语名（text-lg）→ 别名行（text-sm，muted-foreground，无别名则整行省略）→ 释义（text-sm，
   line-clamp-4，卡尾「展开」toggle 可选）→ meta 行（text-xs：来源=Badge muted 态 + 适用范围
   文本；后端缺字段就省略对应项，不造占位文案）。
4. 分页器：复用 Pager；后端无 total 时退化为上一页/下一页二态（以 BACKEND2 返回为准）。

**状态**：选中集合无词条 → SectionCard 诚实空态「该集合暂无词条」；知识库功能未启用/端点 404 →
页面级诚实态卡（说明未启用与启用方式一句话），不放假数据；搜索无结果 → 空态+「清空搜索」按钮；
加载 → skeleton；请求失败 → 错误卡（展示 code/message）。

**交互**：TanStack Query key `[knowledge, collection, q, page]`；搜索 300ms 防抖；切集合/改搜索
词重置 page=1。

## §2 插件页 `/plugins`

**数据**：`GET /api/v1/plugins` → 分组 { builtins, adapters, event_matchers, migrated_modules }，
条目 name / description / source / hot_reload（以 progress-BACKEND2.md 为准）。

**布局**：
1. PageHeader：标题「插件」+ 副题（四组来源说明）。
2. 四组按固定顺序渲染：内置插件 builtins → 适配器 adapters → 事件匹配器 event_matchers →
   迁移插件 migrated_modules。组头 = text-lg 组名 + 数量徽章（Badge，muted 态）。
3. 组内卡片网格 `grid grid-cols-1 md:grid-cols-2 xl:grid-cols-3 gap-4`，卡片（SectionCard）：
   - 名称（text-base，font-medium）；
   - 徽章（Badge，紧跟名称）：`hot_reload === true` → default（品牌）态「热更新即可」；
     `=== false` → secondary 灰态「要重启」；`null` 或缺字段 → 不渲染徽章（三态严格，不许猜）。
     注：任务口径「绿态」与本项目蓝紫 token 调色板冲突（无绿色 token），按既有 Badge variant
     裁定为品牌态；若要真绿色成功态须先在 ui/badge.tsx 增 success variant（走 token），是否增
     设待 WEBUI-FE 席裁决，页内禁止造色；
   - 描述（text-sm，muted-foreground；缺省显示「（无描述）」，不编造）；
   - 来源路径（font-mono text-xs，truncate，title 悬停显全路径）。
4. **无操作按钮期不放假按钮**：本页纯只读，无启停/重载/详情按钮；后端供操作端点时另开规格。

**状态**：event_matchers 组不可用（后端标记不可用/返回 null）→ 整组渲染一张诚实空态卡
「事件匹配器清单暂不可用」，不渲染空网格；某组为空数组 → 组头+「暂无条目」一行（不藏组）；
端点 404/未部署 → 页面级诚实态卡。加载 → 每组 skeleton 卡片占位。

## §3 记忆图谱页 `/memory-graph`

**数据**：`GET /api/v1/memory/graph?window=24h|7d|30d|all&max_nodes=` → stats 六数 +
nodes[{id,label,type: person|group|conversation|memory|rule,…}] + edges + truncated
（字段细节以 progress-BACKEND2.md 为准；max_nodes 前端缺省 200，最终以 BACKEND2 默认值为准）。

**布局**（自上而下）：
1. PageHeader：标题「记忆图谱」+ 副题。
2. 统计卡行：六枚 StatCard（xl 6 列 / md 3 列 / 移动 2 列，gap-4）：人物 / 群聊 / 对话 / 长期
   记忆 / 已学规则 / 发言条数（读 stats，顺序固定）。
3. 工具行（一行 flex wrap，gap-3）：时间窗切换 24h/7d/30d/all（chip 组，选中=品牌色）；
   节点类型多选（**复色视图**）：五类型 chip 可多选，勾选=入图，全不选=自动回到全选（不给空图
   死局）；搜索框：按 label 前端本地过滤（命中节点高亮、其余淡化）。
4. 力导向画布（SectionCard 包裹）：
   - **选型裁决：d3-force（ESM 子包）+ 自绘 canvas 渲染**。理由：d3-force 及传递依赖
     （d3-quadtree/d3-dispatch/d3-timer）gzip 约 +10~15KB，远低于 150KB 预算；确定性可达
     （力初始化为固定 LCG+phyllotaxis 排布，配合固定节点序与固定 tick 数，同 window 同数据必得
     同布局）；自写力导向需复刻 Barnes-Hut 四叉树，bug 面大零收益；recharts 无力导向能力、
     react-force-graph 类库体积/WebGL 超预算，均不引。
   - 渲染为**静态布局**：同步跑固定 300 tick 后绘制一帧，不用动画循环（省 CPU、保确定性）；
     节点半径按度数分 3 档；节点色按类型取 chart token：person→chart-1、group→chart-2、
     memory→chart-3、conversation→chart-4、rule→chart-5；边=对应 token 低透明度描边
     （透明度用 globalAlpha，不造新色值）；canvas 取色一律 getComputedStyle 读 token。
   - 图例：画布下方 chip 行，五类型色点+中文名，与节点色一一对应。
   - 交互：点击节点 → 右侧详情侧栏（SectionCard：名称/类型/关联度/后端返回的节点字段逐项
     展示，未知字段不编造）；hover 高亮邻接边；画布支持拖拽平移+滚轮缩放；画布角落常驻提示
     文案「拖拽平移 · 滚轮缩放 · 点击节点看详情」。
   - `truncated === true` → 画布顶部 info 条「仅显示关联最多的 N 个节点」（N=实际 nodes.length）。
5. **确定性口径**：布局函数写成纯函数（输入 nodes/edges/画布尺寸 → 输出坐标；固定初始化+固定
   tick），导出供单测断言「同输入两次运行坐标全等」；数据未变时切换视图/重开页不重排。

**状态**：nodes 为空 → SectionCard 诚实空态「该时间窗内无记忆关联数据」（提示可换更大时间窗）；
端点 404/未部署 → 页面级诚实态卡；加载 → 画布区固定高度 skeleton 占位。

1. **硬编码扫描门扩展**（扫描脚本由 WEBUI-FE 席交付，脚本名以其 progress 为准）：扫描范围追加

   子组件目录；规则与全站一致（色值字面量 / 任意值字号 / 刻度外间距 / 圆角档外值），预期命中=0。
   脚本未落地前的等价快查（webui/ 下）：
   `rg -n "#[0-9a-fA-F]{6}|rgba?\(|oklch\(|text-\[|\[\d+px\]" src`
2. **组件复用率门**：三页不允许出现脱离可复用组件的一次性样式块。验收口径：三页新增 CSS 类
   定义=0；新增 .css 文件=0；内联 style 仅限画布容器尺寸两处白名单（画布高度、侧栏宽度），
   须在 progress 登记文件+行号。
3. **确定性断言**：§3 布局纯函数入 tests（同输入两次运行坐标全等，容差 0）。

## §6 依赖与风险

- **d3-force**：新增 1 直接依赖+3 传递依赖；单文件构建体积涨幅预估 +8~15KB gzip（预算 <150KB；
  基线=progress-WEBUI Stage E 实测 143.34KB gzip，三页+d3-force 后预估总 gzip <170KB）。
  超预算回退：改自写简化力导向，仅替换布局层、组件接口不变。
- **canvas 高分屏**：按 devicePixelRatio 缩放绘制，否则高分屏发虚（实现注意项）。
- **数据为空/库缺失形态**：知识库未启用/端点 404 → §1 页面级诚实态；插件组缺失 → §2 组级
  空态；图谱 nodes 空 → §3 空态卡。全站纪律：诚实态优先，真页面禁止 mock 数据（dashboard
  mock 演示卡为既有唯一例外且带 mock 徽章）。
- **与并行席冲突处置**：组件签名/端点字段与本文不符时，分别以 progress-WEBUI-FE /
  progress-BACKEND2.md 实作为准；差异由 WEBUI-PAGES2 席在 progress 里记录，不回头改本文
  （快照制）。
