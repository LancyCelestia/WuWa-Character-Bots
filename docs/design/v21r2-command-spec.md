## 1. 目标与范围

用户需求原文：「彻底统一命令指令的格式，要求以 `/bot <一级功能名> <二级功能名> <函数/参数> <函数/参数>` 的形式，要求涵盖：英文、简体中文、繁体中文、拼音全拼、拼音首字母、英文全名、英文简写、中文全名、中文简写。彻底统一命令指令帮助解释说明的格式……先把解释说明文本连同所有命令指令写好，放在新的.md文档里。」

本规格回答四件事：
1. 现存 77 个帮助主题的真值盘点（附录A，逐条可回溯 echo.py 行号）；
2. 统一四段式语法定义 + 14 个一级领域 × 77 个二级功能的归属总表 + 旧→新映射与兼容期方案（§3、§4）；
3. 九形态别名矩阵的规范、全量矩阵与冲突检查（§5 + 条目正文每条九形态行）；
4. 帮助解释统一模板与全量条目正文（§6 + 三个 entries 文件）。

**诚实边界**：用户八大板块思路中的「地点」当前**不存在任何对应能力**（77 主题中无地图/位置/POI 模块，接口清单仅 game_live/gscore 两条 reserved 且与地点无关）——本规格按「需新建」诚实标注，不硬凑（§4.3）。

## 3. 统一四段式语法定义

### 3.1 语法

```
/bot <一级功能名> <二级功能名> [函数] [参数…]
```

- **段1 `/bot`**：固定前缀，别名前缀 `/岸宝` `/守岸人` 等昵称形式等价（现状已支持，alias 层 L10）。
- **段2 一级功能名（领域）**：14 个领域之一（§4.1），标识功能大类。
- **段3 二级功能名（模块）**：该领域下的具体功能（§4.2），与 `/bot help <模块>` 的 topic 一一对应。
- **段4 函数**：模块内的子命令动词（`list/set/add/del/get/查/设…`）。无子命令的模块可省略。
- **段5+ 参数**：逐参数按各条目「逐参数表」填写，个数与类型由该函数定义。可空。

（「四段式」口语计数把 `/bot` 算第一段；形式化语法为 1 前缀 + 2 名称段 + 1 函数段 + N 参数段。）

### 3.2 书写规范（所有新形态别名共同遵守）

1. 拼音：小写、无声调、**不加撇号**（`diange` 不是 `dian'ge`；与既有词表一致）。
2. 英文：小写（注册表匹配大小写不敏感的键统一以小写登记）。
3. 中文：简体为正名，繁体一一对应收录；不用谐音字、不用错别字形态。
4. 分隔：段间用**单个空格**（全角空格兼容，现状 `_strip_prefix` 已处理）；参数内部多值分隔符按各模块现状（`,`/`｜`/空格）。
5. 大小写不敏感、前后空白剥除——与现行 `/bot` matcher 行为一致，规格不引入新差异。

### 3.3 命中与消歧规则

1. **先长后短**：同一领域内多词别名（如 `国债收益率`）优先于单词（`国债`）；多字拼音优先于缩写（`diange` 优先于 `dg`）——现状 capabilities 触发正则已是此语义，四段式解析器沿用。
2. **函数词独占**：段4 函数词若与参数枚举撞名（如 `点歌 link` 冲突提示先例），一律回用法提示，不静默当参数（沿用点歌模块已落地语义）。
3. **让路口径不变**：金融四让路（商品↔行情股词、stocks 兜底、fx 数值优先）、news 裸「新闻」让路、tts 裸词不占路由——四段式只加长命令形态，**不改变既有路由判定序**（T-Spec T2：按 (priority, 声明序) 稳定排序）。
4. 全局唯一性：任何形态（九形态任一格）在**整个注册表**内必须唯一指向一个函数；唯一例外是跨模块同词共谋（现状：`谁` 族），四段式落地时此类共谋词只保留在旧形态兼容层，不进入新矩阵。

### 3.4 兼容期方案（旧触发词→新四段式）

- **兼容原则：只加不改不删**。全部 501 个既有别名 + 自然语言触发 + 裸触发词保持原样可用（它们是 alias/各能力触发正则的一部分，动它=伤生产行为）。
- 新四段式作为**新增形态**并行生效；每个旧触发词在本规格 §4.2 与条目正文中都有唯一映射的新形态（旧→新对照）。
- 昵称层（`守岸人 天气 上海`、`/岸宝点歌 晴天`）：昵称替换后接**旧形态**照旧；接新四段式同样可用（alias 剥前缀后四段式解析器接管）。
- 收敛裁定权在用户：兼容期何时结束（是否回收裸触发词）不做默认裁定，落地席位实施前需用户确认。

### 4.2 二级功能归属总表（77 主题 → 14 领域）与旧→新映射

- **R1** 多主题领域：`/bot <领域> <topic词> <函数> <参数>`，topic 词=帮助 topic 正名。

## 6. 帮助解释统一模板

### 6.1 条目块模板（每条命令一个条目，字段全部必填，缺项写 `—`+原因）

```markdown
#### <序号> <topic 正名>（/bot <领域> <二级>）
```

### 6.2 模板填写规则

1. 参数可用范围**写全**：数字给区间（如 1-200）、枚举给全表（如 black1|black2|white1|white2）、格式给样例（如 YYYY-MM-DD、HH:MM、`1998年3月2日|1998-03-02|1998/3/2`）、长度给上限（如 ≤120 字、≤4000 字）。
2. 每个函数（子命令）单独一行参数表；无参函数写 `| — | 无 | — | — | — | 无参数 |`。
3. 示例必须可复制、与真值源「可复制示例」行同源；新四段式示例按 §4.2 映射书写。
4. 错误反馈不臆造：以 catalog 各模块【失败兜底】【常见错误】【权限与效果】行为准；真值源没写的写 `—（真值源未载）`。
