## 0. 执行摘要：这个项目现在到底是什么情况

**一句话**：这是一个 **1,273 个 Python 文件 / 381,724 行**（含 `tests/` 与 vendored 第三方树）的单体 NoneBot2 插件工程，**物理归类已基本完成、逻辑中央化尚未完成**——代码确实按 21 个功能域归了位，但「一切经中央处理再分发」这条 mandate 在运行期仍不成立：真正的中央是那个 **9,053 行的根 `__init__.py`**，而名义上的中央协议层 **1,931 行、生产零 import**。

### 0.2 最重要的八条结论

1. **中央层是「存在但未通电」，不是「不存在」**。`runtime/capability_protocols.py` 1,931 行，全树仅 6 个测试件与 conftest 引用，生产零 import。它同时是 `creation` 域「诚实对接点」的宿主——所以 **AI 绘画的预留接口不是缺契约，是缺那块契约所依附的、尚未接线的中央层**。
2. **🔴 用户在 `.env` 里填一个未声明的 `BOT_*` 开关键，会被静默丢弃**——填了也开不了门、且无任何提示（`config.py:971-979` 的 `extra="ignore"`，其头注自陈**同类事故已是第 5 次踩坑**）。这是本次排查里对日常使用影响最直接的一条。
3. **人工权威文档已成建漂移，且无门可拦**：`AGENTS.md` 写 529 字段（实 **644**）、6 模板（实 **7**）、20 域（实 **21**）、501 别名（实 **514**）、33 路由（实 **34**）、db 32（实 **30**）——**六项全过期**。仓内唯一禁止手写过期数字的门，作用域只有 2 个文件、正则只有 2 个词。最恶性一条：`backend-protocol-plan.md:46` 把「`--check` 应为 77 topics」写成**可执行期望值**，会把正常的绿判成异常。
4. **坐标类「事实」在本仓系统性失效**：`CODE-MAP` 96 条带行号坐标漂移率 **25%**（但路径与符号名全对 ⇒ 可信度分层明确）；`outbound_registry` 50 条冻结 matcher 坐标错 48–49 条，守它的门 59/59 全绿；全仓**只有 1 个**坐标门真正回读源码。根因之一极具欺骗性：坐标探测器的正则**要求引用必须带 `.py`**（`test_doc_link_integrity.py:208`），所以 `Symbol:line` 形态根本不被当作坐标解析。
5. **`third_party/` 实测是两棵 AstrBot 整仓克隆**（`meme_manager` + `portrayal`，主会话与 L6 各自初报均漏了第二棵），**208 文件 / 30,826 py 行**，全树 gitignored、0 tracked、全仓 0 import ⇒ 死代码，且**未登记**进 `docs/THIRD_PARTY_NOTICES.md`。
6. **文档层已失控**：`docs/` 351 份（含根 22）中 **214 / 329 从未入库**；同一条 NapCat→SnowLuma 术语横幅**逐字重复 44 份**；`docs/design/` 231 份规格里 **228 份与代码零机器接触**——包括自称数值唯一权威的 `affinity-design.md`。
7. **出站终态宣称 ≠ 实际投递**，且横跨后端与语音：TTS 侧 M-63+M-04「拆分/重发/降级三条宣称全假，语音条 0 条而账本记 `sent`」，与本波实测的 A 类旁路（ack/提醒/错误卡/告警/摘要全绕 review+render）、B 类旁路（入群欢迎直调 `call_api`，且正文是手写中文字面量）同根。

### 1.3 处理流程（指针式，不复制正文）

一条 QQ 消息的全程 12 个节点、LLM 子链路 7 节点、渲染链 6 节点、出站链 6 节点、控制面双套事件面——**唯一权威载体是 `docs/CODE-MAP.md §2`**，本件不复制。此处只标注与本审计相关的三个结构性事实：

1. **入口不是 `bot.py`，是根 `__init__.py`。** `bot.py` 只做启动与崩溃守卫；摄取（段归一/引用链递归反查/语音预转码/TG `file_id`→字节）**真身也在根 `__init__.py` 的 `_incoming_from_nonebot_event`**——`domains/chat_reply/runtime/ingress.py` 的 `IngressGateway` 只是 15 行的命名包装（每条消息 new 一个对象再调一次那个函数），**「单一摄取边界」名不副实**。〔初版此处误写为「由 ingress.py 承担」，深读波 D1-1 证伪并已在 §9.4 记账；该误判反过来是 V1-2「事实中央在根文件」的又一佐证。〕
2. **路由有两条并行判定链**：`base_router.classify_message_route`（现役，产出 `RouteKind`）与 `decision/` 影子引擎（缺省 `legacy_only`，**不接管**）。二者对同一条消息各判一次，分歧只记账不干预。
3. **出站有「两套同名事件面」**：`domains/ops/monitor/event_store.py`（V2.1 合同事实面）与 `control_plane/events.py`（控制面自用面），且两边**都有** `EventStoreUnavailable` 类。日志排障时不先看文件名就会修错地方（`CODE-MAP §2.5` 明文警告）。
