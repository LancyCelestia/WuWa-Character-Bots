# 聊天最终自然语言输出

## 本轮原因与处理边界

用户反馈“宝宝”回复仍以多组引号包裹。旧逐句辅助函数在本地可以处理该样例，但只处于早期聊天生成路径；此前没有验证最终渲染层本身能保证纯文本，也没有确定用户运行进程是否加载到了该版源码。本轮不能据此声称已经定位了实机残留引号的唯一原因。

新增 `output/plain_text.py` 的确定性整理，无任何 LLM 调用，不改变人格源文件或发送给模型的 Prompt。
- 在聊天能力完成动作段处理后整理正文，使记忆抽取拿到整理后的回复。
- 最终 `render_reviewed_output` 再处理审核文本/兜底、分段消息及图片说明，覆盖真正发往适配器的文本。
- 仅作用于 `capability_id=bot.chat`；管理员设置、模型配置、帮助命令和媒体 URL 字段不改动。
- 队列审计附加 `chat_plain_text:v1`，便于确认回复经过本轮输出路径；它不是旧进程自动热更新证明。

## 转换规则

- 去除聊天正文的中英文装饰性引号，包括残缺引号、与叙述混排的引号。英文单词内部撇号保留（例如 I'm、don't）。书名号不是本轮删除目标。
- 常见 Markdown 标题、引用、列表、粗体、斜体、删除线和代码围栏转成普通文字；保留段落、顺序和内容，不限制回复字数。
- Markdown 链接保留标签及地址；普通 URL 保护后再处理文字。媒体文件引用不进入整理器。
- 标准 Markdown 表格转换成“列名：内容”的逐行表述。
- 常见 LaTeX 内联/块级公式及 TeX 代码块转换为可读表达：分数、根式、上下标、比较、常见希腊字母、求和/积分范围等，不做数学求值。
- 未知 TeX 命令保留命令名称并标注“公式命令”，不声称可以可靠解释任意宏、矩阵或完整 TeX 文档。源码片段不是自然语言翻译任务，移除展示标记不等同于把任意程序翻译成中文。

## 实机验收

必须重启当前实际运行的机器人进程；不要启动同账号第二个实例。本轮没有给 QQ 群实际发消息。

1. 普通群成员 `@机器人 宝宝`，观察多句回复不再包裹引号。
2. 让机器人说明人物关系，检查标题/粗体变成普通段落，内容没有被强制缩短。
3. 让机器人说明分数或根式，检查不再直接显示常见 LaTeX 标记。
4. 如仍有格式残留，提供对应消息时间与发送 payload 的脱敏文本；先核对请求审计是否存在 `chat_plain_text:v1`，再检查实际运行源码位置。不要贴 API key、Cookie 或完整敏感提示词。
