一、你的核心要求

> **术语说明（2026-09-20）**：文中 `napcat`（日志源枚举）与 `napcat.status`（动作名）是**稳定契约标识符**，未随协议端更换而改名；其**实体自 2026-09-18 起为 SnowLuma**（接入与能力边界见 [snowluma-setup.md](snowluma-setup.md)）。正文凡指「当时接的 QQ 协议端」处已按现役写为 SnowLuma。
当前目标补充（2026-09-17）：完整实施合同见[后端V2.1规范](design/backend-v2-implementation-guide.md)、[产品扩展](design/backend-v2-product-extensions.md)、[验收矩阵](design/backend-v2-acceptance-matrix.md)。本轮仅文档交接，旧要求正文保留；新增算法、计费、自愈、admin实战媒体报告与一次授权规则以上述规范为准，不能当作已实现功能。REST/SSE为本阶段必做，双向实时音频需要时才扩WebSocket。

你要把现有「守岸人 Bot」从“已有大量功能的 NoneBot 机器人”完善为：
统一注册、统一配置、统一开关、统一调度、统一处理、统一人格、统一审计、统一日志、统一指标、统一追踪、统一出站，并可由未来 WebUI 完整控制的后端平台。

本阶段重点是：
- 彻底完善后端；
- 不实现最终前端页面；
- 为未来 WebUI 提供完整、稳定、标准化的 REST/SSE/WebSocket 适配协议；
- 前端未来可以适配 AxonHub 模板或其他模板；
- 所有能力都必须接口化、模块化、注册化；
- 所有开关、参数和控制动作必须能通过统一控制面管理；
- /bot 指令、WebUI、未来 CLI 必须共用同一 Service 层；
- 不允许 WebUI 绕过现有安全链路直接读写文件、数据库、Runtime 或 Python 全局对象。
二、需要保留的项目硬约束
这些来自 AGENTS.md 和现有交接文档，属于执行规则，不是新的业务需求：
1. 能用子代理就用子代理，时刻保持并行满载，以限流为唯一上限；撞限流墙先落盘保进度（断点续跑），子代理结束立即派遣新的子代理补位，直至任务全部完成。主会话不占前台：完成派遣与整合即结束本轮回复、留出对话空间，不在前台长时间卡输出思考。
2. 不执行 git reset、git clean、覆盖或回退现有 WIP。
3. 不修改或删除 ChatBot_Runtime 中的生产数据。
4. 不读取、回传或写入 .env 明文密钥、Cookie、Token、Bearer、生产 Prompt。
5. 不开放任意 shell、PowerShell、cmd、Python 执行。
6. 不开放任意 SQL、任意路径读写或任意原始 NapCat/SnowLuma API。
7. 不进行生产重启、真实模型调用、真实出站、Runtime 迁移，除非获得明确授权。
8. 所有测试、lint、typecheck 和运行结果必须真实执行，不能凭推测汇报。
9. 代码变更必须保持最小化、可回滚，并避免破坏已有工作树。
10. 只有在满足验收条件并有真实证据后，才能称为“完成”“修复”或“可发布”。
